# Phase 6 · 资料库（实体 / 关系 / 时间线 / 半自动派生）

> 目标：资料视图（library：总览/卡片/关系图/时间线）接真。
> 依赖：Phase 3（章节引用）、Phase 5（派生确认走待办卡）。

## 后端现状（已核实）——实体与关系**已存在**

- `routes/library.py`：`GET /api/v2/projects/{id}/library`、`POST …/library/entities`、`PATCH …/entities/{id}`、`POST …/relations`、`DELETE …/relations/{id}`。
- `routes/knowledge.py`：`GET /api/v1/knowledge`、`GET /api/v1/knowledge/{object_type}/{lineage_key}`。
- codex-patches/P0-4：角色实体同步管线（character_synopsis → 实体）已落。
- **开工核对**：library 实体模型的字段集 vs 原型 `design/ws-library-data.jsx` 的实体形状（kind/aliases/fields/首次出现等），差集即为要补的列。记 PROGRESS.md。

## 改动 1 · 实体模型补齐

按核对差集补（预期）：`aliases`(JSON[]) · `first_seen_json`:`{chapter_id, scene_id}` · `status`(active/archived) · `fields_json`（自由字段组，原型卡片编辑器按组渲染）。kind 至少支持 character|location|item|faction|concept。

## 改动 2 · 时间线

- 新表 `TimelineEvent`：`{project_id, label, time_label, chapter_ref, entity_ids:[…], note, display_order}`。
- 端点：`GET/POST /api/v2/projects/{id}/library/timeline`、`PATCH/DELETE …/timeline/{event_id}`。
- 形状对照 `design/ws-library-timeline.jsx` 实际读取的字段（开工时核对）。

## 改动 3 · 图投影

`GET /api/v2/projects/{id}/library/graph` → `{nodes:[{id,kind,name}], edges:[{from,to,relation,note}]}`——纯投影，由实体+关系算出，给 `ws-library-graph.jsx` 用。

## 改动 4 · 半自动派生（⚖️ D5）

- 成稿归档钩子（Phase 7 的写回链）触发 LLM 任务：从新归档正文提取候选实体/别名/时间线事件（任务路由进 `config/models.yaml` + 提示词进 `config/prompts.yaml`，走 `llm_task_runner` 既有模式）。
- 提取结果**不直接入库**：产 idea 卡进待办（`dedupe_key=derive:{chapter}:{name}`），actions=[确认入库(effect `create_entity`/`add_timeline_event`)、忽略]。
- LLM 未配置时静默跳过（沿用 author_action 模式提示，不阻塞归档）。

## 改动 5 · 前端接入

- `ws-library-data.jsx` 的 store 换 API；种子资料并入后端 demo seed。
- P0-4 的雪花角色同步继续作为实体来源之一（雪花第 4/8 步完成 → 人物实体出现/更新）。
- 一次性迁移：旧 library 本地键上行。

## 自检

- 雪花角色步骤完成 → 人物实体自动出现，资料卡可编辑、改名后雪花侧引用不断。
- 建关系 → 关系图即时可见；时间线事件按章排序正确。
- 归档一章 → 待办出现「发现新地点 X」idea 卡 → 确认 → 实体入库进图。
- `pytest -k "library or timeline or entity_derive"` 绿；全量绿。提交：`FE-ALIGN Phase 6: library`。
