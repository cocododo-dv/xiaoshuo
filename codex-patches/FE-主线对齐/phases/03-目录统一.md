# Phase 3 · 目录统一（WsCatalog → ChapterGoal/SceneCard）

> 目标：`GET/PATCH /api/v2/projects/{id}/catalog` 成为章节/场景树的唯一真相源；
> 雪花物化与编排台/写作器写的是**同一批行**。这是全任务最重的一块。
> 依赖：Phase 2。

## 后端现状（已核实）

- `ChapterGoal` + `SceneCard`（`db/models.py`）：`SceneCard.writer_brief_json` 已有 GCS（主动）/RDD（反应）。
- `GET /api/v1/chapters`、`POST /api/v1/chapters`、`POST /api/v1/chapters/{id}/scene-order`（`routes/chapters.py`）。
- 物化主路径：`POST /api/v2/projects/{id}/snowflake-workspace/materialize`（`services/snowflake_workspace.py`）；另有 legacy `outline-plan` + `approve`（`routes/projects.py`）。
- **开工核对**：ChapterGoal/SceneCard 现有列名、`chapters.py` 列表响应形状，记入 PROGRESS.md。

## 改动 1 · 模型扩展（alembic 迁移）

- `ChapterGoal` 增：
  - `narrative_json`(JSON)：`{act, tension(0..1), pov, time_label, place, entry, exit, promise, drama:{promise,spine,arc,problem,aftertaste,ending,forbidden,notes}, threads:[{name,role}]}`（形状抄 `design/ws-catalog.jsx` 的章节对象）
  - `state`(enum: planned/todo/writing/draft/review/approved)、`words_target`(int)
  - `words_current` **不建列**——由场景文档字数实时 rollup，响应里是计算字段
- `SceneCard` 增：`state`(todo/writing/done)、`display_order`(int)、`words_current`(int, 保存正文时更新)。
- slug 兼容：响应为每章带 `slug="ch"+序号两位`、每场带 `slug=章slug+"s"+display_order`（原型 `ch08s3` 格式，⌘K/深链/写作器历史 id 都用它）。不入库，序列化时计算。

## 改动 2 · 目录 API（`routes/catalog.py` 新文件，v2）

| 端点 | 语义 |
|---|---|
| `GET /api/v2/projects/{id}/catalog` | 全树：章（narrative_json 展开 + words rollup + state）→ 场景（brief + state + words + slug），按 display_order |
| `PATCH …/catalog/chapters/{chapter_id}` | 标题/戏剧卡/状态/words_target/threads 局部更新 |
| `POST …/catalog/chapters` | 建章（含「空目录首章立为 writing」语义，抄 `WsCatalog.addChapter`） |
| `PATCH …/catalog/scenes/{scene_id}` | 标题/brief/state 局部更新 |
| `POST …/catalog/chapters/{chapter_id}/scenes` | 插入场景到位置 `at`（待办 effect `insert_scene` 复用此服务函数） |
| `POST …/catalog/scenes/{scene_id}/move` | 章内移动（与既有 `scene-order` 端点二选一复用，不要两套排序逻辑） |

写端点全部要求幂等键；服务层放 `services/catalog.py`，effect（Phase 5）直接调服务函数而非 HTTP。

## 改动 3 · 物化与目录同源（防分叉护栏）

- materialize / outline-plan approve 创建的 ChapterGoal/SceneCard 必须能被目录 API 原样读回。
- 新增护栏测试 `test_catalog_single_source.py`：物化一个项目 → `GET catalog` → 断言章数/场景数/brief 字段一致；目录 PATCH 后再物化不产生重复章。

## 改动 4 · C4 裁决落地（GCS/RDD）

- API 按 `kind` 返回 `brief:{kind:"proactive", goal, conflict, setback}` 或 `{kind:"reactive", reaction, dilemma, decision}`。
- 前端 store 适配层把 RDD 映射进视图用的 `goal/obstacle/turn` 槽位并带 `kindFields` 元数据；唯一允许的视图改动：反应场景的三个字段标签显示「反应/两难/决定」。

## 改动 5 · 前端接入

- `WsCatalog` 内部换目录 API（契约附录列了全部方法；注意 `get()` 同步性陷阱——启动预拉 + 写后失效重拉）。
- `adoptOutline` 改为调物化/outline-plan 链路，删除前端造章逻辑。
- `recordSceneWords` 退化为「保存后刷新」：正文保存端点返回新的字数 rollup，前端不再自算 delta（今日字数/streak 已在 Phase 2 服务端化）。
- 一次性迁移：检测 `arr.chapters.v2::<workId>` 旧键 → 转换为目录 API 批量导入（新增 `POST …/catalog/import` 仅供迁移，admin token 保护）→ 打标记。
- 写作器（`ws-writer.jsx`）的正文文档（`wr-doc:<sid>` 键）→ 接既有正文保存链路（Phase 2 核对的端点）；笔记键 `wr-notes:<sid>` 同步迁移。
