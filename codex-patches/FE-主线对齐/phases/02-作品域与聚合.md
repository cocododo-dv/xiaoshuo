## 后端现状（已核实）

- `snowflake_workspace.py`：**`GET/POST /api/v2/projects` 已存在** —— 本 Phase 的作品列表/创建直接在它上扩展，不要用 v1。
- `routes/projects.py`（v1 legacy）：`GET /api/v1/projects/{id}/dashboard`（已有聚合，本 Phase 对比扩展其逻辑到 v2）、`backtrack-items` + `resolve`、`outline-plan` + `approve`。

- 正文保存主路径**已确认**：`POST /api/v1/author-drafts/{type}/{id}/ensure` + `PATCH /api/v1/author-drafts/{draft_id}`（`author_drafts.py`）——字数埋点加在 PATCH 的服务层。

## 改动 2 · 写作统计服务端化（⚖️ D2 默认：服务端算，Asia/Shanghai）

新建 `services/writing_stats.py`：
- 数据源：正文保存端点在保存时上报 `words_delta`（在既有保存服务里埋点，不另开端点）。
- `GET /api/v2/projects/{id}/writing-stats` → `{words_total, words_today, words_target_daily, streak_days, last_active_at}`。
- streak 规则照抄原型 `catBumpStreak/catEffectiveStreak`（`design/ws-catalog.jsx`）：当天首次正向增量记账；昨天也写过 +1 否则重记 1；断更超一天展示为 0。
- 单测覆盖：跨日、断更、同日多次保存。

## 改动 3 · dashboard 端点对齐

先读现有 `GET /api/v1/projects/{id}/dashboard` 的载荷，与下面目标形状（来自 `design/ws-works.jsx` 的 `home` + 契约附录）求差集，**在 v2 新开 `GET /api/v2/projects/{id}/dashboard`**（D6），内部尽量复用 v1 的聚合逻辑：

```jsonc
{
  "resume":   { "chapter_no": "08", "scene_slug": "ch08s3", "scene_title": "…", "last_lines": ["…","…"], "scene_words": 1240, "paused_at": "ISO8601" },
  "brief":    { "kind": "proactive|reactive", "goal": "…", "conflict": "…", "setback": "…" },
  "snowflake": [ { "step_key": "…", "label": "读者定位", "status": "done|active|warn|todo" } ],
  "chapters_recent": [ { "no": "04", "title": "…", "state": "approved|review|draft|writing", "pct": 100, "active": false } ],
  "stats":    { "…": "同 writing-stats" }
}
```
雪花状态映射：approved→done、当前步→active、skipped 或完整度未达→warn、未开始→todo（数据源 `SnowflakeStepRun`，目录在 `services/snowflake_steps.py` 的 `SNOWFLAKE_STEP_CATALOG`——P0-1 之后是单一真相源）。
纯聚合，**不新增写路径**。

## 改动 4 · flow-status 端点

`GET /api/v2/projects/{id}/flow-status` → 每个域一行：`{snowflake_pct, open_review_count, draft_queue_len, qc_blocked_count, last_manuscript:{no,title,at}}`。给流程视图用，纯聚合。
