# AI 小说结果治理：精简发布路线图（2026-07-15）

## 1. 当前结论

当前主线已经完成 C1/C2 的主要工程闭环，并补齐了运行归档后的状态一致性。本轮进一步完成了 R2.1、C3、C4 的关键工程门禁，但真实模型和真人证据尚未完成，因此整体仍不可标记为发布闭环。剩余工作不再按“功能越多越好”推进，而按发布风险排序：恢复有效模型凭据后先跑来源安全五章，再冻结真人盲评题包，最后执行 30 章耐久。

本路线图坚持三条证据规则：

1. 合成投票不能记作真人盲评；模拟运行不能记作真实 30 章耐久结果。
2. 每个完成结论都必须能回指配置、原始产物、汇总报告和复算命令。
3. 所有代码最终只进入 `main`，不为各阶段长期保留并行分支。

## 2. 执行顺序与完成门

### R2.1：公开来源安全五章 lane（最高优先级）

目的：证明系统能在明确权属、最小云发送策略下，通过真实作者 UI 完成 5 章 × 3 场，并且没有来源专名泄漏、空稿冒充成功或步骤状态冒充结果成功。

固定输入：

- 仓库内公有领域鲁迅短篇语料；来源说明见 `backend/tests/golden/style_reference/README.md`。
- `cloud_policy=segments_only`。
- 显式 `declared=true`、`analysis_rights=true`、`send_rights=true`。
- 固定 5 章、每章 3 场，共 15 场。

完成门：

- 15/15 场均有非空后端归档正文，5/5 章均聚合成功。
- 六阶段 UI 证据完整；不得以 Node 深层 API 代替关键作者动作。
- 来源保护词扫描 0 命中，逐场 source-safety 结论可追溯。
- Q0/Q1 阻断项为 0；运行退出码与 outcome gate 一致。
- 保存配置快照、运行日志、最终场景、门禁判定和汇总报告。

当前进度（2026-07-15）：固定配置、权属传递、动态保护词扫描、归档 provenance、预检入口和契约测试已完成；契约测试（`scripts/tests/`）已接入 GitHub CI 与 `verify_windows.ps1` 门禁。此前一次真实运行尝试在首次 `style_ref_extract_language` 调用处被外部服务拒绝（“该令牌状态不可用”），但其输出目录 `output/playwright/currentdb-three-chapter-qa-20260715-160316` 不在本仓库内（`output/playwright/` 整体被 gitignore，本机检出中也不存在该目录）——按证据规则 2，该次尝试**不可回指原始产物，不作为证据引用**。harness 现已在每次运行结束时把 `report.md` / `outcome-gate-verdict.md` / `source-safety-gate-verdict.md` 自动归档到可入库的 `docs/evidence/<运行目录名>/`，后续运行以该归档为准。工程门已完成，真实 15 场门仍为阻塞状态，不能记作通过。

### C3：30 组真人盲评与默认策略门

目的：回答 Best-of-N 是否真的比单次生成更好，以及提升是否值得额外成本；这是默认策略调整的产品证据，不是单纯的接口测试。

执行内容：

- 冻结 30 组候选对、题目版本、模型/参数与随机化规则。
- 通过现有盲评界面收集真实评审者选择；隐藏候选来源和策略标签。
- 记录评审者匿名标识、时间、题目版本、有效性检查和弃权原因。
- 输出胜率、置信区间、分题材差异、成本/延迟差异及审计清单。
- 仅在预先声明的阈值满足后修改默认策略；否则保持现状。

完成门：30 组均取得合格真人评审，审计来源完整，统计脚本可复算，默认策略决定有明确记录。当前已补齐 fail-closed 证据门：真人题包必须先冻结至少 30 个互异对比对并封存哈希，要求隔离来源和非空评审者；合成票即使达到 21/30，也只能产生统计诊断，不能调整生产策略。报告现已输出偏好率的 95% Wilson 置信区间与分题材（`genre`）拆分；题材标签随对比对入库并进入冻结清单哈希，冻结后改标签会被判定为篡改。`config/outcome-governance-policy.json` 当前明确保持默认单发，作者仍可通过单场“全强度”显式开启 Best-of-N。真实 30 个非平局选择尚未发生，因此 C3 仍未完成。

### C4：真实 30 章耐久、性能与 FK 决策

目的：证明系统不是只在短演示中可用，并决定数据库外键能否安全开启。

执行内容：

- 连续生成和归档 30 章，在第 5/10/20/30 章后执行进程重启与恢复哈希检查（与判定器 `RESTART_CHECKPOINTS` 一致），每 5 章采集一次数据库大小样本。
- 采集场景执行、候选生成、归档、章节聚合的 p50/p95、失败率、重试率和资源占用。
- 对运行中断、重复提交、账本围栏和归档恢复做故障注入。
- 运行全量孤儿数据盘点，并记录 FK 开启前后的测试结果。

完成门：30/30 章结果完整，重启后状态和正文哈希一致，性能未越过发布预算，孤儿记录为 0。只有这些条件都满足才开启 FK；否则保持关闭并形成明确决策记录。当前判定器已改为默认拒绝：必须声明 `real_model` provenance，覆盖唯一的 1–30 章，具备第 5/10/20/30 章重启哈希、每五章数据库采样、三类读取 p95 以及明确 FK 决策；合成报告或缺字段报告不再可能误判通过。真实运行仍受模型令牌阻塞，C4 未完成。

### C5：指标平台与针对性重构

目的：把分散证据变成日常可观察的发布信号，并降低高风险大文件的修改成本。

执行内容：

- 先统一指标字典和 run/chapter/scene 关联键，再做看板；不重复造统计口径。
- 汇总结果门禁、来源安全、盲评、耐久、成本和延迟趋势。
- 按“体积 × 变更频率 × 故障贡献”选择拆分对象，每次只拆一个稳定边界。
- 重构前后运行同一组契约和回归测试，禁止无证据的大爆炸式改写。

完成门：关键发布门在一个入口可查、指标可回溯原始运行；选定大文件完成至少一个无行为变化的边界拆分并通过回归。

### UI 优化与模型/文学质量实验（最后推进）

目的：在可靠性得到证明后提升作者体验和文学质量，避免用视觉润色掩盖状态或结果问题。

优先级：先修状态反馈、错误恢复、键盘操作和可访问性，再做外围页面和视觉美化。模型对比使用同一冻结题集、相同预算口径和盲评流程，文学质量提升必须同时报告偏好、成本、延迟和失败率。

完成门：核心流程无阻断可用性问题；模型结论具备盲评证据且不牺牲硬门稳定性。

## 4. 停止条件

出现以下任一情况时，当前阶段不得标记完成：原始产物缺失、门禁与退出码不一致、使用合成数据冒充真实证据、权属声明不完整、关键 UI 动作被内部 API 绕过、运行结果无法按固定配置复现。
