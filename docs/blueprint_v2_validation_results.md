# v2 蓝图 · §17 验证出口实测结果（动作 B 首次落地）

> 实施日期：2026-06-17
> 分支：`fe-align`
> 性质：把"连续性承诺"从**断言**变成**可证伪的数字**。这是蓝图 §17 明定的"离开蓝图的唯一出口"，此前三份差距文档（gap_analysis / metrics_audit / gap_closure_waves）只走到了模块实现，没有真正跑动作 B。

---

## 0. 一句话结论

事件溯源一致性校验的**真实召回率，在升级前是 0%**——不是 90%，是 0%。

原有的 §17 动作 B 测试（`test_consistency_validation.py`）显示 100% 召回，但那是**虚假信心**：它的 bug 段落是照着校验器的窄字符串模式倒写的。换成真实散文（bug 存在、但不以校验器的字面形式出现），旧校验器一个都抓不到。本次把校验器从"相邻子串匹配"升级为"子句级邻近 + 同义词归一 + 否定守卫"，真实散文召回率 **0% → 100%，精确率保持 100%**。因为该函数正是 hard-QC 闸门所调用，这个提升直接作用于生产生成路径。

---

## 1. 蓝图原话（动作 B 的可证伪判据）

> 拿一段你**已知有连续性 bug 的旧稿**跑，量两个数——
> **召回率**：已知的 bug 抓到了几个？
> **精确率**：报警里有几个是误报（抽取器幻觉）？
> 若召回率低 → 整个系统的连续性承诺都是空的，**停下来修这一层，不要往上加 Best-of-N**。

关键词是"**旧稿**"——真实写出来的、自然语言的稿子，不是为匹配器量身定做的样本。

## 2. 发现：原测试是"测试迁就实现"

`test_consistency_validation.py` 的 4 个 bug 段落，每一句都精确命中校验器的硬编码模式：

| bug | 段落写法 | 命中的硬编码模式 |
|---|---|---|
| 断臂用右手 | "他**右手握**住剑柄" | `limb_actions["right_arm"] = ["右手握", …]` |
| 已死说话 | "**沧澜城城主说**道" | `f"{char}{verb}"`（全名+动词紧贴） |
| 错误地点 | "林远**仍在**沧澜城" | `f"{char}仍在"` |
| 动用失物 | "林远**拿出断剑**" | `f"{char}拿出{item}"` |

只要句式稍偏离——动词与名字之间插入副词、用近义动词、用中文肢体词而非英文键——召回立刻塌方。绿灯掩盖了空地板。

## 3. 实测对照（同一组真实散文，冻结基线 vs 升级后）

新增 `test_consistency_validation_realistic.py`：5 个真实散文 bug（矛盾真实存在但非字面形式）+ 5 个"诱饵"净段（最易误报处）。在同一数据集上同时跑**冻结的旧匹配器**与**升级后的检测器**。

| 测试段落（真实散文） | 旧匹配器 | 升级后 |
|---|---|---|
| 断臂角色"抬起右手…握住长刀"（非"右手握"紧贴） | 漏 | ✅ |
| 断臂角色"双手握住长枪"（蓝图的"双手握剑"范例） | 漏 | ✅ |
| 已死城主"缓缓睁开双眼…开口"（非"全名+说"） | 漏 | ✅ |
| 角色"依旧待在沧澜城"（非"仍在/还在"） | 漏 | ✅ |
| 角色"握紧了那柄断剑"（非"拿出/掏出"） | 漏 | ✅ |
| 5 个诱饵净段（回忆/墓前、左手健全、正确返回、泛指失去、一致独白） | 净 | 净 |

```
UPGRADED (clause-level)   recall=100%  precision=100%  F1=100%   (tp=5, fp=0, fn=0)
NAIVE    (pre-upgrade)    recall=0%    precision=0%    F1=0%     (tp=0, fp=0, fn=5)
Recall lift on realistic prose: 0% -> 100%
```

该对照被钉成断言（`naive recall ≤ 20%` 且 `upgraded recall ≥ 80%` 且 `precision ≥ 90%`），既是证据也防止退回窄匹配。

## 4. 升级了什么（`narrative_event_log.py`）

`_check_fact_against_text` 由"整段相邻子串"重写为**子句级**检测：

- **子句切分**：按中英文句读/逗号/引号切成子句，"同一子句内共现"作为邻近代理，兼顾召回与精确。
- **同义词归一**：`right_arm` / `右臂` / `右手` / `right hand` 归一到同组；动作动词集大幅扩充（握/攥/抓/举/抬/挥/拔/持…）。
- **"双手"分支**：断一臂后用"双手/两手/双臂/十指 + 动作"判为矛盾——直接覆盖蓝图点名的"双手握剑"。
- **否定守卫（保精确率）**：
  - 已死角色：子句含"想起/回忆/生前/临终/墓/灵位/尸…"等回忆框架 → 不判矛盾。
  - 断肢：子句含"断/残/失去/空荡荡/仅存/伤口…" → 视为在描述残缺本身而非动用。
  - 失物：子句含"失去/丢了/想起/怀念…" → 视为追忆而非动用。
- **地点错位**：把已知地点集（含角色 location fact 值）传入，仅当"角色 + 滞留措辞 + 错误地点"且未提正确地点时才判，避免把"还在沉睡"误判为地点矛盾。

调用点 `check_consistency` 增加 `known_locations` 收集（地点既可能是 location 实体，也可能是角色的 `location` fact 值）。

## 5. 诚实边界（§15）：现在硬/软各归何处

| 矛盾类型 | 归属 | 例 |
|---|---|---|
| 字面硬事实矛盾 | **确定性关键词层（阻断）** | "抬起右手握刀"、"双手握剑"、"依旧待在沧澜城"、"握紧断剑"、"城主睁眼开口" |
| 隐含/需推理的矛盾 | LLM 建议层（`llm_flag`，仅人工抽检，不阻断） | "拉紧两侧的缰绳"（暗示双手却没出现"双手"字样） |
| 软事实（关系微妙、语气一致） | **放弃自动校验** | 蓝图明确放弃 |

`check_consistency_llm` 的混合策略保持不变：关键词层是权威阻断层，LLM 至多 1 次、仅建议、无 runner 即退化、失败不抛。本次升级把一批原本只能靠 LLM"建议"的字面误用，提升为关键词层的"确定性阻断"——更便宜、更可靠。

## 5.5 §6 Best-of-N 对抗排序器实测（第二项体检：这次是好消息）

把同一套科学方法推进到第二圈核心——`adversarial_rank_score` 的"管下界"承诺：自动初筛能否把最 AI 味的候选排到最后？用配对稿实测（同一场景的"AI 注水稿" vs "show-not-tell 干净稿"）：

| 场景 | 注水稿 rank | 干净稿 rank | margin | 触发对抗维度（注水/干净） |
|---|---|---|---|---|
| 信件焚毁的告别 | 0.534 | 0.773 | +0.239 | 8 / 3(仅结构维) |
| 门外脚步的逼近 | 0.614 | 0.773 | +0.159 | 7 / 3(仅结构维) |
| 战后归来的重逢 | 0.500 | 0.773 | +0.273 | — |

结论：**排序器确实能判别**——注水稿恒排在干净稿之下，Best-of-N 的 argmax 在 [注水, 注水, 干净] 池中必选干净候选。与连续性校验不同，§6 的下界**不是剧场，是真的**。

两点诚实记录：
- **结构维度（painless/no_choice/choice_pressure）会在纯氛围干净稿上触发**。它们是 §4 结构维、非散文 AI 味维，但混入排序器是**合理的**：对"同场景 N 候选"排序时，它恰好惩罚没兑现 §4 代价的候选；对无选择的过渡场景则对所有候选等量作用、不扭曲排序。
- **只管下界、不管上界（§6.2）**：干净稿 rank≈0.77 而非 1.0，这段残差正是 §6.3 交给人去终选的空间。测试**刻意不断言**排序器能挑出"最好"的散文，只断言它能滤掉"最差"的。

落成永久判据 `test_best_of_n_selection_validation.py`（9 用例）：下界排序、注水多触发、Best-of-N 选干净、分散度信号、"地板非天花板"诚实断言。若未来有人翻转极性、抽掉对抗维、或塞进奖励规整的顺从性指标，这些断言会立刻炸响——这正是 §6.5 指标审计前置门的长期守卫。

## 5.6 §5 伏笔生命周期复核（已有真实覆盖，顺手补一处"假绿"）

对第一圈另一承重机制（契诃夫之枪）同样做了可证伪复核。结论：**§5 与 §2 不同——它的覆盖是真的**。`test_foreshadow_lifecycle.py` 实测了过期→高优先 payoff、强化间隔触发、埋设密度过载告警、resolved 不误报等失败模式，是货真价实的判据，无需重复造测试。

唯一发现是同一种"虚假信心"病的小剂量：`test_consecutive_without_payoff_detection`（§5"回收荒漠"检查）此前用 `if report.density_warning:` 包断言——一个无论功能好坏都会通过的**永不失败测试**。已收紧为真断言（确认 15 场景零回收时告警确实触发）。这与本文 §2 的核心教训同源：**绿灯不等于被验证，要看测试能不能失败。**

至此 §17 可证伪覆盖横跨三大承重机制：§2 连续性（曾是剧场→已修）、§6 Best-of-N 下界（验证为真→锁定）、§5 伏笔（已真实覆盖→补牢一处假绿）。

## 5.7 §6 对抗维度消融：一个被证伪的假设（§17 终极问题的维度级回答）

§17 的终极问题是"每个模块何时该被砍掉"。团队的 metrics_audit 按**意图**给 18 个对抗维度分了类；我再进一步，按**实际是否在真实中文稿上判别**来量——做了一次维度级消融。

提出并检验了一个可证伪假设：

> 假设：不少对抗维度只认英文词（moon/turned/because…），在中文小说系统里是**死重**，该砍。
> 结果：**证伪**。词表本就是双语的，每个对抗维度在条件满足时都能在中文上触发。首轮看着"死"的三个其实是**条件/阈值门控**：`repetitive_action` 需同一动作 ≥4 次、`false_poetic_closure` 需"诗意收尾且无具体动作"、`self_repetition` 需跨场景上下文（单段不可测）。

中文语料（6 注水 / 6 干净）消融结果：ranker 均值 slop=0.634 / clean=0.773（margin +0.138），**11–12 个散文维度正判别**（syntax_monotony +0.50，model_voice/false_clarity/decorative_imagery/perception_filter 各 +0.33…）。

唯一真实细节落在**结构维**：`painless_scene`/`no_choice_scene`/`choice_pressure` 在注水稿与干净稿上**几乎等量触发**（判别≈0，`no_choice_scene` 甚至 −0.17 轻微反向）。它们度量的是 §4 场景结构、不是散文 AI 味。对"同场景 N 候选"排序而言这是近似常数偏移（可接受），但意味着**散文排序器的判别力来自 12 个散文维、不是这 4 个结构维**。这是观察、不是 bug——结构维在 §4 QC 处挣它的饭；是否该从 prose 排序里单拆出来，留作设计建议。

要点：**一个被证伪的假设也是 §17 的胜利**——确认"这套维度都在挣饭吃"和砍掉一个死模块同样有价值。锁成 `test_adversarial_dimension_ablation.py`（5 用例）：若未来有人剥掉某维的中文词表（退回英文死重）或翻转极性，断言会炸。

## 5.8 §17 Best-of-N 上界盲测 harness（把"需要人"的那一半做成一条命令）

§6.2 钉死：对抗排序器只管**下界**（已验证机器能滤掉最差）；**上界**——"过了下界的候选里，人是否真更喜欢多花 5× token 选出的那个"——只能由人判。这是 §17 唯一卡在"需要人"的核心判据。我能在约束内推进的，就是**把测量机器造好，让人来跑判断**。

新增 `services/best_of_n_blind_eval.py`（纯逻辑，20 用例全测）+ `tools/best_of_n_blind_eval.py`（CLI）：

- **盲化**：每场把 Best-of-N 选择（复用流水线真实 `adversarial_rank_score` 的 argmax）对阵单发基线（N=1 会得到的那个），匿名洗牌进 A/B、隐藏映射——评判者看不出哪个是哪个。
- **计票**：把 A/B 票经隐藏映射折回 treatment/control 胜负。
- **统计**：精确二项检验（双侧默认保守 / 单侧可选，匹配"是不是更好"的方向性问题）+ `min_n_for_significance`（要多少次盲测才够）。
- **裁决**：偏好率 + p 值 + 透明的成本-收益结论（justified / marginal / no_detectable_benefit / need_more_samples）。"值不值"的阈值是**带标签的可配置判断旋钮**（蓝图明说这是判断、不是科学），不假装客观。
- **诚实计入**：Best-of-N 与单发选了同一候选的场景记为 `no_contrast`（它在这里没产生价值，计入 ROI 反方）。

顺带一个诚实的统计发现：**蓝图自己的锚点"38/60，p 值已低"在精确双侧检验下其实是 p≈0.052（临界、不过 0.05）**，单侧才 p≈0.026。sidedness 与"精确 vs 近似"都重要——harness 两者都给，默认双侧（保守）、可切单侧（方向性）。

跑法：`python -m novel_system.tools.best_of_n_blind_eval demo`（合成端到端）；真实测量 `plan --candidates … --out plan.json` 出盲票 → 人评 → `tally --plan … --votes …` 出裁决。**人来跑、我把仪器交付**——这是 §17 上界判据从"待办"变成"一条命令"。

## 6. 独立复核：模块层 vs 蓝图（确认团队自评，并标出仍存的真实缺口）

本次借 5 个并行代理对照蓝图全节做了独立代码级复核，结论与团队三份文档基本一致：**模块层完成度约 90%+**。仍存的真实缺口（按价值排序，**尚未在本次修复**，留作后续）：

1. **§7 解码端最强杠杆缺失**：仅接了 API 的 `frequency_penalty`/`presence_penalty`，蓝图点名的 **XTC / min-p / typical / DRY 全无**（因走 API 而非本地模型）。XTC 恰是对抗趋均值最锋利的刀。建议：为草稿步加一条本地模型通道。
2. **§4 代价"轴位移"自动校验缺失**：只校验 `cost_requirement` 字段是否填写，未实现蓝图的"追踪轴上的值有没有变，没变就是注水"。可复用事件溯源做场景前后状态求差。
3. **§9 Few-shot 主写作路径存疑**：`_render_few_shot` 能力存在且带漂移感知，但多书叠加路径主动丢弃 few-shot，`scene_generation` 不直接引用——需确认写作任务默认策略真的注入了 few-shot（蓝图称其为"注入端主武器"）。
4. **§2 POV 是"叠加"非"过滤"**：`format_state_for_prompt` 仍注入全部角色状态再补 POV 已知信息，非"投影只含 A 的已知集"。
5. **§11.2 决策权重等距线性插值**：未实现"关键转折大跳变、普通场景微调"的非均匀迁移。

## 7. §17 仍未完成的部分（下一步，不是再加模块）

动作 B 已对**连续性**这一层落地。蓝图要求"**每个模块都配一个可证伪判据**"，以下仍是断言而非测量：

- **Best-of-N 偏好率盲测（上界）**：下界已由 §5.5 验证。上界的**测量仪器已造好**（§5.8 的盲测 harness + CLI）——剩下的纯粹是**人去跑**：拿真实候选集出盲票、人评 ~30-60 次、`tally` 出裁决。这一半按蓝图本就归人，现在只差执行。
- **关键增强层的消融**：批判修订 / 漂移"展示"修正 / 混合一致性各跑一个对照，量出各自的边际贡献。
- **§16 过约束体检**：同一场景跑 `constraint_intensity = 1.0 / 0.5 / 0.0` 三版盲读，找地板与生命力的真实权衡点（目前滑块有旋钮、无标定）。

> 原则（蓝图 §17 收尾）：完美的方案不是模块最全的，而是每个模块都可证伪、知道何时该被砍掉的。下一块钱应投向"测量与人的判断接缝"，不是第 26 个模块。
