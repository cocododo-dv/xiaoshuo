# 风格参考候选评分与重排

## 目标

多候选生成原先只按 `adversarial_rank_score` 排序。该分数用于淘汰已知坏稿，
不回答“候选是否更贴合本次实际应用的 StyleReference Profile”。本模块在保留
质量下限的前提下增加第二条、可解释的风格信号。

它不承诺“像人”或“无法被 AI 检测”，也不把自动统计冒充文学质量上界。
它只衡量候选与已冻结参考画像在可观测文本统计上的相对贴合度。

## 信号与约束

- 只读取 `profile_json.metrics_baseline` 的 18 项文本可观测指标；依赖段落分类器的
  8 项比例指标不参与候选评分。
- 指标按句式、标点节奏、语体、修辞代理、感官代理五组先组内聚合，再组间等权，
  避免指标数量多的组天然占优。
- 多层 Profile 沿用注入层“由泛到具体、权重递增”的合成顺序。
- 候选不足 300 个实质字符、可用指标少于 12 项或置信度不足时，不允许参与主动重排。
- 主动模式只能在距最佳确定性质量分不超过 `max_quality_drop` 的候选间选择；
  风格权重硬上限为 0.25，质量差距硬上限为 0.08。
- 规范化后连续复刻来源语料达到 12 字会被独立 guard 后置，并且不会进入关键场景的
  作者候选终选池。审计只保存命中数量与长度，不保存来源原句。

## 发布模式

配置位于 `config/style_reference/candidate_rerank.yaml`：

- `shadow`：当前默认。计算并持久化风格诊断，但不让未校准风格分数改变质量排序；
  来源复刻 guard 仍生效。
- `active`：必须同时带有冻结的人类盲评报告 ID 与 SHA-256，并声明
  `human_verified=true`、`policy_evidence_eligible=true`，否则自动退回 `shadow`。
- `off`：关闭风格分数；来源复刻仍作为不可弱化的安全约束。

当前跨内容自动基准明确标记为 `policy_evidence_eligible=false`，因此不能直接开启
主动重排。需要先完成隐藏集生成，再做人类盲评，证明风格贴合提升且质量不下降。

## 可复算审计

每个候选随 `style_ready` checkpoint 保存：

- 原质量分、风格分、置信度和五组分；
- 最大偏离的指标名与标准化偏离比；
- 是否执行来源重叠检查、命中数与最长命中长度；
- 实际排序模式、选择原因、Profile ID、目标统计哈希；
- 冻结 bundle Profile ID 与运行时 binding 是否一致。

排序审计本身有 checkpoint 哈希。进程恢复时会校验候选身份、正文哈希、排序审计哈希，
然后恢复相同顺序；旧 checkpoint 没有该字段时仍可兼容读取。

## 已知边界

- 18 项统计是可解释的低成本代理，不足以覆盖视角控制、叙述距离、意象系统和潜台词等
  高层风格，因此主动模式必须由隐藏人评证据授权。
- Profile 的抽象画像、Binding 策略与多层顺序现已由
  `style_reference_runtime_contract_v1` 冻结进 Bundle。评分从快照构造目标；实时契约哈希
  与冻结哈希不一致时降为 shadow，契约缺失/损坏也不会旁路到实时 Profile。
- 评分不读取题材、专名、作者名或向量语义，不会因“写了相同主题”而获得更高风格分。
